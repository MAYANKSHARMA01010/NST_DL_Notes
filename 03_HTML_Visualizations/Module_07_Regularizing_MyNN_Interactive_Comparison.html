Regularizing MyNN

Why the Fashion-MNIST network overfits, and exactly which lines of code L2, Dropout and BatchNorm change. Every run uses seed 42, lr 0.1, batch 32, 100 epochs.

Baselineno regularization
+ L2Part 1 · changes the optimizer

Missed the demo? The whole story

  1. Baseline overfits. Train accuracy keeps climbing while test accuracy stalls, so the gap keeps widening.
  2. + L2 shrinks the gap. One optimizer argument keeps the weights small and holds train accuracy back.
  3. + Dropout + BatchNorm shrinks it further. Dropout does most of this; BatchNorm mainly steadies training.
  4. Test accuracy barely moves. Regularization stops memorizing; it doesn't add accuracy. The goal is good test accuracy with a small gap, not the smallest gap.

    A model overfits when it memorizes its training data instead of learning the pattern. Train accuracy keeps climbing, test accuracy stalls, and the distance between them is the gap.
    
    
    
      
    
      
    
        
    In the notebook
    
        
      
          
    • MyNN has 109,386 weights and learns from 48,000 images: plenty of room to memorize.
      • 
          
    • The baseline's plot_curves shows it: the solid train line pulls away from the dashed test line, and the shaded band widens.
      • 
          
    • Test loss may even start rising while train loss keeps falling. That's the model fitting noise.
      • 
        
    
        
    Three fixes, added in order

    L2 regularization penalizes big weights. Every update also pulls each weight a little toward zero, so the network can't build the large, spiky weights it needs to fit noise.
    
    
    
      
    
      
    
        
    Loss = CrossEntropy + (λ/2)·Σw²
    w ← w − lr·(∇CE + λ·w)
    
        
    The code: one argument, model unchanged
    
        
    
        
      
          
    • weight_decay is λ. With SGD it adds exactly the λ·w term above.
      • 
          
    • Same MyNN and same loop as the baseline, so any change in the gap is L2's doing.
      • 
        
    
        
    Watch out: λ is a knob. Too small and nothing changes. Too large (try 1e-2) and the gap disappears but test accuracy drops too. That's underfitting.
    
      
    
    
    
  
    

  
  
    
    
    Dropout switches off a random 30% of a layer's neurons on every training step, so no single neuron can memorize an example. In eval mode it does nothing.
    
    
    
      
    
      
    
        
    The code: after each hidden ReLU
    
        
    
        
      
          
    • 0.3 is the probability of dropping a neuron, not keeping it.
      • 
          
    • In train mode the kept values are scaled by 1 / (1 − 0.3) ≈ ×1.43, so the layer's total output matches eval mode on average.
      • 
          
    • It only runs after model.train(). evaluate() calls model.eval(), so accuracy is measured with every neuron on.
      • 
        
    
        
    Watch out: train accuracy should drop. The network is working with 70% of its neurons on every step.
    
      
    
    
    
  
    

  
  
    
    
    BatchNorm rescales each neuron's outputs across the batch to mean 0 and std 1, then lets the network learn its own scale (γ) and shift (β). Its main job is faster, steadier training; the batch-to-batch noise regularizes only a little.
    
    
    
      
    
      
    
        
    x̂ = (x − μbatch) / √(σ²batch + ε)
    y = γ·x̂ + β
    
        
    The code: after each hidden Linear
    
        
    
        
    Watch out: BatchNorm makes the training data easier to fit, which can partly cancel Dropout. That's why the dropout rate has to be tuned together with the rest of the model.
    
        
    train() vs eval(): what changes
